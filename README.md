# 萬巒鄉預算資料庫

> 把一本本掃描的預算書，變成**可搜尋、可下鑽、可跨年度比較**的公開資料。

> ### ⚠️ 使用聲明
> - **一切資料以萬巒鄉公所公布之預算書原件為準。** 本專案僅供**快速比對與查閱**之用。
> - 本專案資料由 OCR 轉檔並經程式驗證整理，**可能存在誤差**，不具官方效力。
> - **請勿將本專案之資料、數字或圖表引用於其他地方**（含報導、報告、公開發言、文件等）；如需引用，請直接查閱並引用鄉公所公布之原書。

**屏東縣萬巒鄉**的年度總預算書原本是掃描 PDF：不能搜尋、難以複製、更無從跨年度比較。本專案將它轉成結構化資料與互動式網站，**每一筆數字都標示預算書的頁碼**，讓居民、記者、研究者與民意代表都能快速比對、回到原書查證。

- 網站：<https://show7587.github.io/WanluanBudget/>
- 收錄年度：**114、115、116** 三個年度的總預算案
- 資料格式：開放的 CSV 與 JSON，金額一律以**元**為單位

## 為什麼值得用

| | |
|---|---|
| **每個數字都能回到原書** | 歲入、歲出每一列皆附預算書頁碼，114 年度另附 PDF 頁序對照與原書截圖。 |
| **嚴格的自動驗證** | 細目加總＝子目＝項＝款，計畫加總＝用途別＝政事別，歲入、歲出與機關別總表交叉比對；每次建置都逐一檢查，報告公開在 [`reports/`](reports/)。 |
| **誠實揭露，不偷改** | 對不上的數字不會被「修正」，而是如實列出；原書本身的錯字與前後不一致，保留原樣並以 **ⓘ** 標註。 |
| **三年一次看** | 逐年趨勢、相鄰年度比較，歲入歲出、不同層級的項目都能放在同一張圖上看。 |
| **零依賴的資料管線** | 後端只用 Python 標準函式庫；前端為純靜態網站，可直接部署在 GitHub Pages。 |

## 怎麼使用網站

用上方選單切換年度與功能：

| 功能 | 可以做什麼 |
|---|---|
| **總覽** | 歲入、歲出總額與收支差短；歲入來源、歲出政事別、經常門與資本門的結構圖；與前一年度的長條對照。 |
| **歲出** | 三種視角切換：**政事別**、**機關別**、**用途別**。從大項目逐層點進去，直到最細的明細，並可用樹狀圖檢視比重。每列都有預算書頁碼。 |
| **歲入** | 「款 → 項 → 子目 → 細目」逐層下鑽，細目含單位、數量、單價、說明與收入依據。 |
| **比較** | 相鄰兩個年度（114→115、115→116）的金額增減與百分比，範圍可選歲出工作計畫、用途別，或歲入款、項；可篩選「新增／增加／減少」，新出現的項目以「新增」標示。 |
| **趨勢** | 跨 114–116 看單一項目的逐年金額，可切換**金額／年增率／指數**，並可自選最多 **8 個項目**（可跨歲入、歲出與不同層級）同圖比較。需至少兩個年度的資料。 |
| **搜尋** | 輸入關鍵字，查名稱、說明或編號，可只看歲入或歲出；結果可直接跳到「看趨勢」。 |
| **參考表**（僅 114） | 依原書頁碼瀏覽預算書末的參考表，例如人事費彙計、公務車輛明細。 |
| **資料備註** | 預算書印刷錯字、前後不一致、版面限制與資料缺口的完整紀錄，可依類型與頁碼篩選。 |

小提示：
- **網址會記住你的檢視狀態**（年度、頁面、下鑽路徑、視角、趨勢項目），可直接複製分享。
- 圖表與資料表可**匯出 CSV／JSON**。
- 版面可在手機上使用。

### 看到 ⓘ 是什麼意思

預算書原件偶爾有印刷錯字，或同一個數字在不同頁印得不一樣。本專案**不會偷偷改掉**，而是照原書保留，並在該列旁加上 **ⓘ**。點開可以看到：

- 原書印的是什麼字、資料庫存的是什麼、建議的正確寫法
- 在原書第幾頁、PDF 第幾頁
- 當時如何核對，以及原書截圖

舉例：114 與 116 年度第 59 頁把「自治條例」印成了「自治修例」。搜尋「自治條例」或「自治修例」，都能找到這一筆。

## 資料內容

所有資料放在 [`data/`](data/)，是一般 CSV，可用 Excel 或任何工具開啟。每個年度一個資料夾（`data/114/`、`data/115/`、`data/116/`）。

| 檔案 | 內容 |
|---|---|
| `summary.csv` | 各種總表：歲入來源別、歲出政事別、歲出機關別、收支簡明比較等，含本年度、上年度、前年度決算 |
| `revenue_items.csv` | 歲入明細：名稱、單位、數量、單價、金額、說明、頁碼 |
| `plans.csv` | 歲出工作計畫：編號、名稱、承辦機關、政事別、總額、頁碼 |
| `expenditure_items.csv` | 歲出明細：各計畫下每個用途別的說明、金額、經費來源、頁碼 |
| `reference_tables.csv`（僅 114） | 預算書末的參考表內容 |

共用檔案：

| 檔案 | 內容 |
|---|---|
| `data/memos.csv` | 資料備註表（錯字、前後不一致、版面限制、資料缺口） |
| `data/corrections.csv` | 轉檔時的 OCR 修正登記，每筆都寫明依據 |
| `data/crosswalk/codes.csv` | 預算書改編號時，新舊代碼對照 |
| `docs/evidence/` | 備註對應的原書截圖 |

網站實際讀取的 JSON 在 `site/data/`（由建置腳本產生），也可直接取用。

## 資料可信嗎

- 預算書自帶多層加總關係，專案每次都逐一驗證，三個年度的驗證報告都在 [`reports/`](reports/)：

  | 年度 | 歲出計畫 | 用途別 | 機關別 | 備註 |
  |---|---|---|---|---|
  | 114（`--partial`） | 50／50 | 291／291 | 2／2 | 20／20 |
  | 115 | 48／48 | 300／300 | 2／2 | 5／5 |
  | 116 | 49／49 | 296／296 | 2／2 | 3／3 |

- 對不上的地方**不會自動修正**，而是如實列出。**通過驗證代表內部加總一致，不代表與原書逐字相同**——說明、名稱這類沒有數字約束的欄位仍可能有 OCR 誤差。
- 少數問題出在原書本身，這些保留原樣、登記在資料備註並等待向公所確認，例如：114 稅課收入前年度決算在第 1 頁與第 6 頁印得不同；116 第 1 頁上年度歲出基準與第 10 頁前年度決算合計有不一致。已知問題與待辦整理在 [`docs/TODO.md`](docs/TODO.md)。
- 114 年度部分頁面缺書面原件可逐一對照，細節見 [`CLAUDE.md`](CLAUDE.md) 的「已知限制」。
- 逐年趨勢資料另有獨立檢核（`scripts/check_series.py` 直接由 CSV 重算並比對，D1–D9 全數通過）。

### 目前限制

- 比較只支援相鄰年度；明細層級（說明欄各列）的跨年度配對尚未接進網站。
- 參考表僅 114 年度提供；114 的 p159 人事費彙計表缺「備註」欄（原件該欄無內容，OCR 漏掉）。
- 資料以公所公布之總預算書為準，**僅供快速比對與查閱，不得引用於其他地方**。

## 在自己的電腦上開啟網站

需要 Node.js 20 以上：

```bash
cd web
npm ci
npm run dev
```

用瀏覽器開啟終端機顯示的網址（預設 <http://localhost:5173>）。網站讀取 `site/data/*.json`，原書截圖（`docs/evidence`）也會一併提供。測試用 `npm test`，正式建置用 `npm run build`（輸出 `web/dist`）。

技術棧：Vue 3、TypeScript、Vite、ECharts、MiniSearch；資料管線為 Python 3.14（僅標準函式庫）。

### 重建資料（進階）

```bash
python3 scripts/parse_book.py 116          # OCR 原文 → CSV
python3 scripts/validate.py 116            # 驗證並產生 reports/validate_116.md
python3 scripts/build.py                   # 產生 SQLite 與 site/data/*.json
python3 scripts/check_series.py            # 趨勢資料獨立檢核
python3 -m unittest discover -s tests      # Python 測試
```

114 年度需加 `--partial --reference-tables`。完整流程與規則請看 [`CLAUDE.md`](CLAUDE.md)。
