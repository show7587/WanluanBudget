## 2. 資料特性（已實際觀察到）

- **頁碼要用推算的**：md 裡沒有頁碼，但每一頁開頭都保留了表頭。Part3 中歲入明細的表頭出現 24 次（= 目錄的 p37–60），歲出明細的表頭出現 96 次（= p61–156）。表頭有 OCR 變形，例如 `## 鄉總預算案`、`## 屏東縣萬巒`、`# 歲出計畫說明提要與各項費用明細表`，要用「歲入項目說明提要」、「歲出計畫說明提要」這兩個關鍵字來比對。
- **編號**：歲入細目是 11 碼，例如 `01120010201遺產及贈與稅-遺產稅`，出現在「來源別子目及細目編號」欄；歲出工作計畫也是 11 碼，例如 `33120010101一般行政-行政管理`，出現在「業務計畫及工作計畫名稱與編號」欄，116 年約有 49 個；用途別是 4 碼加名稱，例如 `2033 約用人員酬金`。
- **續頁**：一個細目或計畫可能跨好幾頁，續頁沒有編號表頭，資料列的第一欄是空的。例如 `09120010102` 計畫型補助收入就跨 p53–57。
- **歲出明細的結構**：用途別列（例如 `2000 業務費`、`2033 約用人員酬金`）會帶小計，下面接沒有用途別、只有單位／數量／單價／預算數／說明的明細列。
- **OCR 錯誤**：
  - 數字黏連：例如 `4,000,0004,000,000`
  - rowspan 位移：例如 `1055 保險` 的小計 560,000 跑到其他列
  - 名稱遺漏：p40 的 `01120011401` 沒有名稱，照順序應該是房屋稅
  - part1 第 87 行有一段亂生的「Theorem 1.2…」文字，是雜訊
- **總表之間數字互相矛盾**：上年度歲出，簡明比較分析表寫 267,169，收支簡明比較分析表寫 271,169；機關別比較總表的前年度決算是 322,278，其他表是 353,260。
- **金額單位**：總表是千元，明細表是元。CSV 一律存成「元」。

## 3. 架構

```
raw/<年度>/part1.md, part2.md, part3.md     # 原始轉檔，永遠不修改（用 git mv 搬過來，順便改正年度）
data/<年度>/                                # 正規化 CSV，是 source of truth，放進 git
  summary.csv            # year,source_book,source_table,page,款,項,科目名稱,本年度,上年度,前年度決算
                         #   唯一鍵 (year, source_table, 科目)；不同表之間互相矛盾時兩筆都保留，不自動挑一個
  revenue_items.csv      # year,page,code,name,item_seq,unit,qty,unit_price,amount_元,note,dept
                         #   續頁的列歸給前一個細目，page 記實際所在頁
  plans.csv              # year,page_start,page_end,plan_code,name,dept,政事別,總額
  expenditure_items.csv  # year,page,plan_code,用途別_code,用途別,unit,qty,unit_price,amount_元,說明,經費來源,item_seq
data/corrections.csv     # 人工修正 OCR：year,page,locator,field,old,new,reason（parser 讀進來套用，raw 保持不動）
data/crosswalk/
  codes.csv              # 跨年度編號對照：from_year,from_code,to_year,to_code,note
  items.csv              # 明細項目對照：item_id（穩定 ID）,kind(revenue|expenditure),year,scope_key,item_seq
                         #   scope_key：歲入用細目 code；歲出用 plan_code+用途別_code
scripts/
  parse_book.py <年度>   # raw md → data/<年度>/*.csv（含頁碼推算、套用 corrections）
  validate.py <年度>     # 加總檢查 + 跨表交叉驗證 → reports/validate_<年度>.md
  match_items.py         # 明細項目跨年度候選配對 → data/crosswalk/items_candidates.csv
  build.py               # CSV → build/budget.sqlite + site/data/*.json + 搜尋索引
tests/                   # unittest；fixtures/ 放預期值
site/                    # 純靜態網站，不需要前端 build 步驟
  index.html, app.js, style.css, data/   # data/ 由 build.py 產生
```

技術選擇：
- **Python 只用標準函式庫**：`html.parser`（rowspan／colspan 自己展開成二維格子）、`csv`、`sqlite3`、`difflib`、`unittest`。不要引入 pandas 或 BeautifulSoup。
- **前端用原生 JS（ES modules）**，不需要 build 步驟。圖表用 ECharts，搜尋用 MiniSearch，都從 CDN 載入並鎖定確切版本。
- **前端的資料用 JSON**：`site/data/<年度>.json`、`index.json`（年度清單、跨年度對照）、`search.json`。
- SQLite 只給本機查詢用，不部署。

### 頁碼推算
- 依目錄每一節的起訖頁數，每遇到一個該節的表頭，頁碼就加一。
- 每一節都要驗證「表頭數 = 目錄頁數」，不相等就**報錯中止**，不要猜。
- 每一筆記錄的 `page` 記它實際所在的那一頁；計畫要記 `page_start`／`page_end`。

### 明細項目跨年度配對
1. 配對範圍限定在同一個 scope 之內：歲出是（計畫編號，經 crosswalk 對應）×（用途別），歲入是同一個細目編號（經 crosswalk 對應）。
2. 先把說明文字正規化：去掉年度字樣（「115年度」改成 `<年>`）、函文字號、標點和空白。
3. 正規化後完全相同的，自動配對；`difflib` 相似度 ≥ 0.75 的列為候選，寫進 `items_candidates.csv`，由人工確認後併入 `items.csv`。
4. 沒有配對到的就當作新增或刪除項目。
5. 要等第二個年度匯入後才能真正驗證，在那之前用人造樣本寫單元測試。

### 驗證規則（validate.py）
- **數字欄位**：遇到無法解析成單一金額的儲存格（例如千分位黏連），一律標記為異常並寫進報告，**不能靜默轉成整數**。只有登記在 corrections.csv 的才算處理過。
- **歲入明細**：每個細目的明細列 amount_元 加總，要等於區塊表頭的「預算金額」（千元）× 1000，20 個細目逐一列出結果。
- **總表之間的衝突**：summary.csv 中同一科目、同一欄位在不同 source_table 的數值不同時，要列進報告並附各自的頁碼。
- **歲入**：細目加總要等於子目，再到項、款，最後等於總計 312,678 千元（對照 part1 的歲入來源別預算總表）。
- **歲出**：明細加總要等於用途別小計，再等於計畫總額，最後等於政事別合計，總計 321,081 千元（對照 part1 的歲出政事別預算總表）。
- **跨年度**：只做到 summary.csv 的款／項層級。N 年預算書裡的「上年度預算數」要等於 N-1 年預算書裡的「本年度」，第二個年度匯入後（S5）啟用。
- 每一項檢查都把結果（通過／失敗，附頁碼）寫進報告。**對不上的不自動修正**。

## 4. 網站功能（S4 起）
- 年度總覽：收支簡明、歲入來源別和歲出政事別的 treemap，以及經常門和資本門的比例。
- 歲出瀏覽：表格逐層展開，政事別 → 機關 → 工作計畫 → 用途別 → 明細，每一列都顯示預算書頁碼。用 URL hash 帶篩選條件，例如 `#/116/歲出?政事別=教育科學文化支出`。
- 歲入瀏覽：款 → 項 → 子目 → 細目，同樣附頁碼。
- 計畫／科目詳細頁：跨年度折線圖，加上各年度的明細列表，標示新增、刪除和金額增減。
- 比較增減：任選兩個年度，依增減金額或比率排序。
- 搜尋：關鍵字跨所有年度搜尋說明、名稱和編號，可以依年度和歲入／歲出篩選。
- 手機寬度（約 400px）可以正常使用。

## 6. 實作規則
- **不要修改 `raw/` 底下的任何檔案**。OCR 錯誤一律透過 `data/corrections.csv` 修正，每一筆都要有 reason。
- 用 corrections 修正數字時，正確值要能從同一個表格的其他欄位（單價×數量、表頭金額、上一層小計）推導出來。推不出來就列進報告，交給使用者決定，不要自己猜一個數字。
- 不 commit、不 push、不部署，除非使用者明確要求。
- 每一片都只新增檔案，加上一次 `git mv`，回滾用 `git revert`。
